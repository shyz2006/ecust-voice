# CampusPulse（校园脉搏）架构说明

面向高校心理中心：了解学生在关注哪些社会热点、梗文化和短视频玩法，用来指导心理中心策划活动。
它以 BettaFish（微舆）为基础，挂载在 `/pulse` 路径下，与原有的三引擎 + 论坛流程并存，互不替换。

## BettaFish 原架构的三个局限

| 局限 | 表现 | 对心理中心的影响 |
|---|---|---|
| 被动触发 | 必须先输入问题才开始分析 | 老师往往不知道该问什么，恰恰需要系统主动告诉他们"学生在聊什么" |
| 固定拓扑 | 每个问题都启动 Query、Media、Insight 三个 Agent 加论坛 | "某个梗是什么意思"这类简单问题也要跑完整流程，耗时长、花费高 |
| 缺少验证 | 论坛讨论之后直接生成报告 | 编造出处、跑题这类错误会一路传到报告里 |

## 新架构：感知层 + 自适应推理层

```
            ┌──────────── 感知层（常驻，统计方法，LLM 只标注新内容）──────────────────────┐
 热榜 8 源 ─→│ 加速度草图 → 跨平台聚类 + c-TF-IDF → 校园心理透镜（三维风险）   → 热点雷达 │
 B站热门 ──→│ 标签/BGM/投稿活动/热评 + 视频镜头切换 × 音频节拍（后台队列）            │
            │   └→ 梗与玩法发现：新词 / 句式模板 / 同款信号 → LLM 精筛 → 扩散曲线 → 梗与玩法 │
 狐友本校圈 →│ 去标识化 → 帖子主题 / 情绪 / 危机标注 → 近 7 天聚合（对比全国校园）→ 本校声音 │
            │ 两阶段提交：抓取(fetched) → 分析结果原子提交(complete)；中断后自动补做           │
            └──────────────────────────────────────────────────────────────────┘
                                         │ 老师点击“深度解读 / 策划活动”或直接提问
            ┌──────────── 推理层（按需）──────────────────────────────────┐
 问题 ────→ │ 拓扑路由器 → 工作流选择器(UCB) → 编排器(任务账本/进度账本)          │
            │   ├ 工具：梗词典记忆 / 热榜侦察员 / 博查检索员                        │
            │   ├ 推理：单智能体写手  或  解读专家 ∥ 心理透镜专家 → 活动策划专家     │
            │   └ 结构规范化 → 中心验证器(MAST) ──未通过──→ 补充检索 + 修订（停滞即止）│
            │ 通过 → 正式结果 / 梗词典 / 奖励；未通过 → 待人工复核草稿（不发布、不学习）   │
            │ 正式结果 + 老师评分 ──→ 奖励 ──→ 工作流选择器（在线自我优化）            │
            └─────────────────────────────────────────────────────────────┘
                                         │ 全网深度舆情类问题
                                         └→ 移交 BettaFish 三引擎 + 论坛
```

## 各设计点与论文对应

| 模块 | 文件 | 借鉴 | 本项目的改动 |
|---|---|---|---|
| 突发检测 | `burst.py` | TopicSketch：用两个时间尺度的速度之差作为"加速度"，用哈希草图存储状态 | 热榜观测按名次折损加权；按真实时间差做连续衰减；冷启动时把基线直接设为稳态值 |
| 话题聚类 | `topics.py` | BERTopic：先嵌入再聚类，最后用 c-TF-IDF 提取主题词 | 短标题改用字符 n-gram 嵌入，再用阈值 + 并查集聚类，不需要下载模型 |
| 梗与心理标注 | `lens.py` | Computational Meme Understanding 综述：按形式、功能、主题三维给梗分类 | 补充了转场、BGM 卡点、发疯文学等短视频语境下的形式；把话题映射到 11 个大学生心理维度；风险拆成心理危机 / 内容安全 / 选题价值三条独立维度 |
| 梗与玩法发现 | `memes.py` | 梗理解综述中的“模板型梗”；经典新词发现（邻字熵 + 凝固度） | 不依赖标题点名：在评论、帖子、标签中发现新流行语与句式模板；同款 BGM / 标签 / 投稿活动作为模仿信号；逐批记录出现量形成扩散曲线；LLM 精筛并缓存“非梗” |
| 剪辑特征 | `video_features.py` | —— | ffmpeg 场景切换检测 + 频谱通量起音检测，计算切点与拍点对齐的提升倍数，识别卡点剪辑 / 快切转场；视频临时下载、分析后删除 |
| 本校声音 | `sources/huyou.py`、`campus.py` | —— | 只读公开页面、丢弃用户标识并脱敏；帖子主题 / 情绪 / 危机标注按内容缓存；只展示聚合与去标识化摘要，危机信号只计数 |
| 结构规范化 | `agents/schema.py` | MAST 中的“智能体间契约失配” | 从证据说明文字中提取编号、对象字段转文本，避免把有效证据误判为伪造、前端显示 [object Object] |
| 拓扑路由 | `agents/router.py` | Towards a Science of Scaling Agent Systems：可分解任务适合多智能体；顺序依赖、工具密集的任务适合单智能体；中心化验证能抑制错误传播 | 按任务可分解度、工具强度、顺序深度三项特征选择：单智能体、中心化多智能体，或移交 BettaFish |
| 编排器 | `agents/orchestrator.py` | Magentic-One：用任务账本和进度账本组成双循环 | 修订后得分没有提升即判定为停滞并停止，避免空转 |
| 中心验证 | `agents/verifier.py` | Why Do Multi-Agent LLM Systems Fail?（MAST 失败分类） | 把 FM-1.1、1.3、2.3、3.1、3.3 做成确定性检查，并加上心理领域的安全检查（污名化用语、危机干预提示）；伪造证据编号属于硬失败 |
| 工作流自优化 | `agents/workflows.py` | AgentSquare（模块化设计空间）、AFlow 与 GPTSwarm（基于反馈优化工作流） | 原方法在基准上离线搜索，这里改为在线选择：UCB 按验证得分、老师评分和 token 成本挑选工作流 |
| 记忆 | `agents/workers.py` | AgentSquare 中的记忆模块 | 通过验证的梗释义写入梗词典，后续分析作为 M 类证据复用 |

## 可信度与口径（第三轮）

| 问题 | 做法 |
|---|---|
| 梗候选精度 | 三级证据：**平台实测出现**（语料有真实频次）/ **外部热点线索**（仅检索或媒体提及，永不标“新出现”）/ **已验证趋势**（连续多批次增长且至少两类独立来源，或老师确认）；只有第三级显示“正在流行”。常用口语词与创作激励类投稿活动在规则层过滤；老师的“不是梗 / 过时词 / 普通词 / 重复候选”标注直接屏蔽该候选，并作为否定样例进入模型精筛提示 |
| 本校社区口径 | 页面统一称“本校公开社区信号”；SimHash（去标点后的字符 3-gram，汉明距离 ≤8）合并相似帖；各平台热度先做来源内分位数标准化再合并；灌水楼 / 交易 / 失物招领降权且不附心理维度；显示覆盖平台、有效样本、观察天数、置信度；连续观察满 7 天（`PULSE_TREND_MIN_DAYS`）才给出趋势 |
| 具体转场手法 | `transitions.py`：只对统计模型判为卡点 / 快切的视频，取最多 6 个切点前后各 1 帧，一次视觉模型请求判断手法（动作触发换装、遮挡、甩镜、推拉、动作匹配、场景匹配、手势触发…）与触发动作，按玩法名聚成“转场玩法”模板；每天限额 `PULSE_VISION_PER_DAY` |
| 验证 ≠ 正确 | 新增主张—证据逐条蕴含检查（事实主张“不支持”即硬失败）、来源分级（A 官方/主流、B 平台原帖、C 普通媒体、D 梗百科/自媒体）与交叉验证；页面区分“观察事实 / 模型推断 / 活动建议”；通过自动验证的称“AI 验证稿”，活动方案须教师复核后才标“可执行” |
| 性能与成本 | 三条独立队列：抓取 + 快速分析（只用规则与缓存，秒级原子提交）→ 模型增强（独立线程，只标注新内容，完成后原子刷新视图）→ 视频 / 视觉分析；多智能体先生成共享事实包；按任务类型设定输出 token 上限（截断时自动加倍重试一次）；“工作流看板”展示各阶段耗时、模型调用 / token / 失败与缓存命中率 |
| 外部源故障 | 公开热榜全部失败时沿用上一批公开话题并标注时间；抓取错误保留在批次统计中并在状态栏告警 |

## 隐私与安全

- 公开热榜与 B 站热门只保存公开元数据；视频仅临时下载用于剪辑分析，分析后删除，只保留数值特征。
- 狐友本校圈：只读公开页面，不调用带签名的接口；入库前丢弃用户 ID、昵称、头像，并隐去手机号、微信 / QQ 号、邮箱、学号等长数字与 @ 提及；不保存帖子链接。
- 本校危机信号只计数、不展示原文（`PULSE_SHOW_CRISIS_EXCERPTS=1` 时显示去标识化摘要）；对个体的干预应按学校心理危机干预流程由人工在原平台核查。
- 所有事实性结论都要引用证据编号（H 热榜 / W 网页 / M 梗词典），由验证器核对；未通过验证的结果只作为草稿，经老师复核才能转正式。
- 心理危机等级只能升不能降；涉及危机信号的输出必须附带危机干预提示，例如转介心理中心、全国心理援助热线 12356。

## 配置（均可选，写在 BettaFish 的 `.env` 中）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PULSE_LLM_API_KEY` / `_BASE_URL` / `_MODEL_NAME` | 沿用 `QUERY_ENGINE_*` | CampusPulse 使用的 LLM |
| `SEARCH_TOOL_TYPE`、`BOCHA_WEB_SEARCH_API_KEY`、`BOCHA_BASE_URL` | 与 Query Agent 相同 | 博查搜索 |
| `PULSE_SOURCES` | weibo,douyin,bilibili-hot-search,zhihu,tieba,toutiao,baidu,thepaper | 热榜来源 |
| `PULSE_COLLECT_INTERVAL_MIN` | 30 | 后台采集间隔（分钟），设为 0 则关闭 |
| `PULSE_DB_PATH` | `data/campus_pulse.db` | SQLite 数据库路径 |
| `PULSE_MAX_REPLANS` | 2 | 修订轮数上限 |
| `PULSE_HUYOU_CIRCLES` | 空 | 本校狐友圈子 ID（页面“本校声音”中粘贴链接保存，优先于此项） |
| `PULSE_HUYOU` / `PULSE_BILIBILI` | 1 | 是否采集狐友 / B 站 |
| `PULSE_VIDEO_ANALYSIS` / `PULSE_VIDEO_PER_BATCH` | 1 / 8 | 是否做视频剪辑分析 / 每批次最多分析的新视频数 |
| `PULSE_SHOW_CRISIS_EXCERPTS` | 0 | 是否在本校声音中显示危机帖的去标识化摘要 |
| `PULSE_TIEBA_FORUMS` | 空 | 本校贴吧名（页面中设置优先） |
| `PULSE_TREND_MIN_DAYS` | 7 | 本校社区信号给出趋势结论所需的最少观察天数 |
| `PULSE_VISION_PER_DAY` | 40 | 每天转场手法视觉识别的最大视频数 |

## 测试

```bash
python -m pytest CampusPulse/tests -q
```

测试用假 LLM 和假搜索覆盖以下内容：路由选择、草图加速度估计、跨平台聚类、验证器识别伪造证据、危机提示检查、"验证→修订→复核"循环、UCB 选择工作流；
结构规范化、验证失败转草稿（不写记忆、不计奖励）、人工复核、批次原子提交与中断恢复、三维风险分层、狐友脱敏、梗与同款信号发现、卡点剪辑识别。
